## 已修复问题

1. 多个页面直接初始化模拟业务数据；房态日历按日期编造价格/库存。改为从空集合加载，Mock仅显式开启时动态导入，真实日历缺失日期显示“未设置”。
2. 商家订单数组与其他订单分页不一致，首批结果被二次分页。三端订单统一`{total,pages,list}`和服务端分页；仍使用本地表格的房源/用户页面加载所有分页，避免首100条被当成全部。
3. 用户取消与超时竞争重复恢复库存、商家取消后仍为已支付、平台任意改状态。统一OrderService行锁、合法转换、退款及日志；库存和房态维护统一RoomInventoryService及房型锁。
4. 未配置房态日期仍能下单。与搜索/详情统一：任意晚缺失库存即拒绝；编辑可售库存不得超过房型总量扣除预订量。
5. 收藏软删除后重新插入触发唯一键冲突。增加显式幂等PUT/DELETE、复用唯一记录及用户锁。
6. 禁用旧JWT仍有效、管理员返回密码哈希。每次访问核对数据库状态/当前角色，密码与身份证字段不可序列化。
7. 支付结果相信URL参数、重试生成新requestId。改为查询服务端状态、复用预订requestId及已创建订单，提交时禁用按钮，按服务器金额核对价格变化。
8. 独立复核发现刷新令牌成功后重试500被改成401并清空会话。已用失败单测复现并修复；业务失败保留原错误，只有真实认证失效才退出。
9. 仪表盘写死交易额、入住率、来源及风险事件。改为真实指标或暂无数据；未实现的导出/账号安全操作不再假报成功。

## 复现

前端目录：`npm test`、`npm run lint`、`npm run build`、`python scripts/reliability_test.py`。后端设置本机JDK17的JAVA_HOME后执行`mvnw.cmd test`，默认使用隔离H2，不需要业务库。

真实集成脚本默认访问本地2223；Vite需通过`VITE_BACKEND_URL=http://127.0.0.1:8082`代理最新后端，再执行`python scripts/reliability_real_api_test.py`。可用`TEST_BASE_URL`指定其他本地地址。

MySQL测试必须新建专用空库，通过`BOOKING_TEST_DB_URL`、`BOOKING_TEST_DB_USER`、`BOOKING_TEST_DB_PASSWORD`、`BOOKING_TEST_DB_DRIVER=com.mysql.cj.jdbc.Driver`指定，执行`mvnw.cmd -Dtest=BookingConsistencyTests test`。测试会初始化表并清理测试数据。

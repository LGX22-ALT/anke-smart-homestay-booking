# 电脑与手机布局交付记录

日期：2026-11-19。状态：已实现并完成本轮验证。

## 需求与方案

同一个页面链接根据屏幕与触屏条件自动使用合适布局，保留数据、路由、AI 推荐、预订和账号功能。采用同一套 Vue 业务组件及独立响应式样式，避免复制两套业务代码造成差异。

- 电脑：完整顶部导航、居中内容、多列推荐与后台常驻侧栏。
- 手机：紧凑页头、首页/酒店/景点/我的底部导航、双列推荐、横向推荐提示、紧凑搜索结果与适合触控的表单。
- 粗指针触屏在 1024px 以下保持手机导航，覆盖手机横屏；普通窗口 768px 以下切换。后台侧栏使用 800px 断点。
- 后台手机抽屉支持遮罩关闭、关闭按钮、Escape、Tab 焦点循环与焦点返回；关闭时释放背景滚动锁，切回宽屏时恢复主内容交互。
- 手机账户菜单改为点击打开，保留账号入口与退出登录；底栏预留页面空间和设备安全区。

## 问题、原因、难点与验证

| Bug | 原因 | 解决方式 |
| --- | --- | --- |
| 手机继续使用电脑式顶部导航 | 代码检查及旧截图显示窄屏仅将顶部导航换行，缺少手机专用布局；新导航基线测试失败 | 新增手机底栏和媒体查询，桌面隐藏底栏、保留顶部导航。难点是相同路由适配触屏横屏且不遮住内容，采用视口/指针条件、安全区及底部留白；224 次尺寸检查和 iPhone 触屏模拟通过 |
| 账户菜单依赖悬停 | 代码检查发现原 popover 使用 hover，不适合作为触屏主要入口 | 改为点击打开，手机头像按钮提供可读标签、菜单内提供退出。难点是隐藏桌面文字按钮后仍保留完整账号操作；真实浏览器完成手机菜单退出、再点击“我的”跳登录 |
| 后台手机抽屉缺少完整关闭和焦点管理 | 原布局只有菜单开关，无遮罩、明确关闭按钮和焦点处理 | 加入遮罩、44px 关闭按钮、Escape、焦点循环/返回、背景 inert 和滚动锁，监听窗口变宽恢复。难点是不能让手机打开状态影响随后电脑布局；遮罩、Escape、Tab 和跨断点恢复均通过 |

样式检查补充：搜索结果在手机使用缩略图与信息并排，表单字号调整为 16px；桌面保持原有构图。没有新增后端接口或数据库变更。

## 改动位置

- `src/assets/responsive.css`：独立桌面/手机布局、导航、安全区、触控尺寸、搜索与后台窄屏规则。
- `src/main.js`：加载响应式样式。
- `src/components/common/NavHeader.vue`：手机导航、点击账户菜单、手机退出入口。
- `src/components/layout/BackOfficeLayout.vue`：手机抽屉交互和监听清理。
- `scripts/responsive_layout_test.py`：离线账号数据、页面尺寸和交互验收。
- `scripts/responsive_public_test.py`：真实本地接口页面验收。
- `DESIGN.md`：记录统一设备布局规范。

按 UIUX Pro Max → Frontend Design → Taste → GSAP → Impeccable 顺序核对，沿用项目品牌和已确认首页，不增加装饰动画。Impeccable 沿用先前记录的启动器限制，以项目规范、浏览器与截图验收，未宣称专用引擎通过。

## 实际测试结果

- 离线测试数据：32 条页面路径 × 7 组尺寸，共 224 次检查通过。覆盖首页、搜索与搜索结果、酒店详情、景点、攻略、历史、对比、帮助、用户中心、订单确认/支付结果、商家及管理后台、登录。
- 尺寸：1440×1000、1024×900、820×900、768×1024、390×844、360×800、667×375；无文档横向溢出，无页面运行错误。数据表内部滚动继续保留。
- 手机交互：底部酒店/我的路由跳转、账户菜单退出、未登录访问“我的”跳登录；后台遮罩/Escape/焦点循环/焦点返回及宽屏恢复通过。
- Playwright 的 iPhone 13 设备模拟：触屏点击酒店导航、844×390 横屏保持手机导航通过。这是浏览器设备模拟，未声称真机测试。
- 真实本地接口：6 个公开页面 × 电脑/手机两种宽度通过；酒店接口 HTTP 成功且业务 code=200，无运行错误。
- `npm test`：31 项通过；`npm run lint`：0 错误、0 警告；`npm run build`：通过。
- 初轮抽屉恢复断言读取了尚未完成的视口更新；改为等待 DOM 状态后重测通过，没有把异步布局时序写成产品缺陷。

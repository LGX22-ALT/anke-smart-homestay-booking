# 前后端可靠性整改计划（2026-11-15）

目标：真实 API 失败时不显示模拟业务数据；并发订单不超卖、不重复恢复库存；禁用账号立即失去访问权限；收藏操作可重复执行。

沿用 Vue 3、Spring Boot/MyBatis 和既有页面风格，直接按本次用户授权执行。当前目录没有 Git 元数据，不创建提交或覆盖现有工作。测试使用隔离内存数据库及独立浏览器上下文。

## 验收条件

- AC1：Mock 仅在 VITE_USE_MOCK=true 时动态加载；业务页面从空集合开始，区分加载、失败和无数据，失败可重试。
- AC2：订单列表统一 `{total,pages,list}`，页码至少 1、每页 1–100；用户、商家、管理员均按服务端分页展示。订单 VO 包含真实房源名、入住人、状态和金额，不接收客户端金额作为结算金额。
- AC3：订单状态只通过 OrderService 修改；先锁订单，再锁房型/日历。取消、超时和退款成功只恢复一次库存；退款中保留库存，退款完成恢复未入住订单库存，已完成入住后的退款不恢复历史库存。非法转换拒绝且无副作用。
- AC4：禁用/删除用户的已有 access token 与 refresh token 均不可使用。收藏增加 PUT/DELETE 明确目标状态，重复请求不重复插入，重新收藏可用。
- AC5：自动化覆盖并发争抢最后库存、重复请求、取消与超时竞争、商家取消、退款库存、失败回滚、禁用账号和重复收藏；浏览器验证真实 API、接口失败、空状态、分页及窄屏。

## 审查重点

缺失日期房态不可用；退款重试及完成订单退款不可重复加库存；用户不能操作他人订单；禁用旧令牌不能绕过；分页不能只加载首屏再假装全量搜索。

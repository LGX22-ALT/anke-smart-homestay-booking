# 商业化页面与城市内容

目标：游客能从首页使用 AI 搜索推荐，并按同一城市探索酒店和景点。按用户最新要求，移除首页目的地与日期搜索区，将 AI 搜索推荐移回首屏；酒店列表原有搜索入口保留。

设计选择：沿用紫色品牌，以深蓝文字、浅灰背景、白色内容卡片呈现。首屏突出目的地搜索和城市旅行入口，AI 助手保留在住宿推荐之后。酒店展示位置、设施、起价；没有评价时明确显示暂无评分。新增酒店为演示数据，不编造真实商家评价。

方案比较：纯样式精修无法解决城市空数据；整体重建品牌影响既有操作。本次选择完善现有 Vue 页面与本地数据。

- [x] R1 首页：搜索表单、推荐酒店信息层级、窄屏适配。位置：Home/index.vue。
- [x] R2 景点：首页和探索页城市筛选、详情到对应城市住宿。位置：travel.js、Explore/index.vue。
- [x] R3 数据：8 城各新增 6 家演示酒店、3 个房型及未来 180 天库存；幂等 SQL 与 Mock 同步，保留原数据。
- [x] R4 验收：lint、build、数据库计数、浏览器城市切换、景点详情、搜索和手机宽度。

基线：2026-11-15 lint/build 通过；本地 API 可用；数据库仅杭州 2 家酒店，景点仅广州 5 个。

结果：本地库总计 50 家酒店，杭州 8 家、其他城市各 6 家。新增 144 房型、25920 条房态记录。景点总计 50 个（广州 8 个，其余各 6 个），保留旧景点路由。42 个增量条目取得图片，实际使用的 45 个新增条目中有 7 个使用文字导览；没有用其他景点照片填充。Wikimedia 图片随条目保存作者、授权与来源链接。

自动验收：`python scripts/commercial_catalog_test.py`，实测 8 城切换、景点展开数量、景点到住宿链接、景点城市和关键词筛选、真实 API 房型详情、日期搜索参数、360/390/768/1024/1440 宽度无横向溢出、无页面运行时错误。截图：`test-artifacts/commercial-home-desktop.png`、`test-artifacts/commercial-home-mobile.png`。

浏览器：Chrome DevTools 检查首页城市切换返回正确数量；酒店 API 与 AI 状态请求 HTTP 200，控制台无 error/warn。AI 服务原本未启用，保留其现有状态，没有测试模型回复。没有执行真实支付。

SQL：`../hotel-back/sql/migrations/20261115_demo_city_catalog.sql` 已在本地库执行两次，计数保持不变。重建数据可运行 `scripts/expand_catalog.py` 生成增量 SQL 和同步 Mock 数据，SQL 不覆盖原有行。新增条目 ID 在 2000–2075，房型 ID 在 20001–20753，目标商家沿用本地演示商家 ID 1。

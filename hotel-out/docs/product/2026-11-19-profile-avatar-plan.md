# 用户与商家头像、个人名称

目标：用户在个人信息、商家在个人资料修改展示名称、上传头像或选择默认头像，保存后页头立即同步，刷新及重新登录保留。

方案：复用账号表 name/avatar 与认证的 profile 接口，抽出共享编辑器和头像组件，商家增加 /merchant/profile。复用账号资料而不新增商家独立字段，避免两端显示不一致。默认头像为六个站内 SVG，上传采用独立认证头像接口并在服务端校验和裁切，避免依赖外部头像服务。用户原有手机号修改保留。

技术：Vue/Pinia + Spring Boot/MyBatis，沿用紫色品牌、系统字体、44px 控件和响应式规则；不引入新依赖或装饰动效。

实施：

- [x] 后端先补 H2/MockMvc 测试：两角色保存/重新登录、局部更新不丢字段、拒绝空名称及无效头像、上传有效及无效图片、未登录与账号隔离。
- [x] 实现头像存储（JPG/PNG、5MB、尺寸校验、中心裁切 PNG），名称校验与局部资料更新。
- [x] 前端补校验测试，抽取共享编辑器和头像显示，接入资料页及导航栏；处理保存/加载/失败/重试/重复提交与预览释放。
- [x] 运行隔离数据库浏览器流程，验证两角色上传、默认头像、修改名称、刷新、重新登录与窄屏；执行前后端检查并记录证据。

审查补充：共享编辑器的模拟数据响应补齐账号标识，保证演示模式也能保存并同步名称和默认头像。只读审查发现并发局部更新可能丢失另一项资料；先用屏障测试复现，再改为只提交请求中的字段，重新读取返回结果；复查无阻断项。

结果详见 `2026-11-19-profile-avatar.md`。当前由 IDE 启动的本地后端需要重启，才能加载新增接口；未终止 IDE 调试会话。

验收边界：不修改登录方式、店铺名称或订单规则；测试使用独立 H2 与临时账号，不保存认证信息到报告或截图。

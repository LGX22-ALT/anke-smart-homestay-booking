# AI 对话独立页面

日期：2026-11-20。用户要求：AI 输出时进入专门对话界面，并在首页导航新增入口。保留原有 AI 推荐接口、回答模式和酒店卡片，不新增模型或后端存储。

## 实现方式

- 首页 `AiStayAssistant` 只负责输入和入口校验，提交后跳转 `/ai-chat?q=...&mode=...`；独立页先检查 AI 状态，再自动提交 URL 中的问题，避免首页继续承载完整结果。
- `/ai-chat` 复用 `getAiStatus`、`searchWithAi` 和 `normalizeHotel`。消息按用户/AI 分组，AI 返回的筛选条件、推荐房源和“查看全部房源”继续使用现有数据结构。
- 当前浏览器会话用 `sessionStorage` 保存消息和推荐结果，刷新后恢复；按当前城市分开存储。未接入服务端历史记录，不虚构跨设备同步。
- 页面支持自动/深度思考/快速回答、连续追问、清空对话、加载状态、离线重试、发送失败保留原文并重试。输入快捷键处理 Ctrl/Command+Enter，不影响中文输入法确认。
- 桌面使用居中工作区；手机保留消息滚动区、输入区和五项底栏中的 AI 入口，沿用项目紫色品牌和现有导航组件。不添加 GSAP 动画或新依赖。

## 发现的问题、原因与解决

| Bug | 原因 | 解决方式 |
| --- | --- | --- |
| 从首页进入 AI 页面后问题没有自动发送 | 页面挂载时状态检查和 URL 问题提交并发，提交先读到 `checking` 被直接返回 | `onMounted` 先完成 `getAiStatus`，再处理 `q` 参数并发送；原首页入口回归通过 |
| 独立页面点击发送时报事件对象错误 | Vue 表单 `@submit` 会把 `SubmitEvent` 传给 `send(prefill)`，函数误把事件调用 `.trim()` | `send` 只接受字符串预填问题，表单提交和“重试”事件统一走当前输入；错误回归通过 |
| AI 请求失败后点击重试会出现重复用户消息 | 失败时保留用户气泡和草稿，重试又无条件追加一条相同气泡 | 保存失败轮次 ID，原文重试复用原用户气泡；回归断言重试前后用户消息数量不变 |
| 带城市参数的 AI 深链使用旧城市 | 页面读取了 `q/mode`，没有将首页带来的 `city` 写入应用城市状态 | 提交前同步 `route.query.city`，深链请求体已验证使用深圳 |
| 新增 AI 后手机底栏列数不匹配 | 既有 CSS 固定四列，新增入口会挤压每个导航项 | 桌面顶部导航新增 AI，手机底栏改为五列，保留 44px 操作区域 |
| 手机进入私信页时“我的”不高亮 | 底栏仅根据 `/user/` 路径判断激活状态 | 将 `client-messages` 纳入“我的”激活条件 |
| 连续发送多条消息后提示 `history: 个数必须在0和6之间` | 前端把当前新消息也放进历史，并取最近 7 条；后端接口限制历史最多 6 条 | 组装请求前排除当前会话，历史只保留之前最多 6 条；新增连续追问回归断言 |

问题发现方式：第一轮浏览器回归中首页跳转后只显示空对话；控制台明确出现 `SubmitEvent.trim is not a function`。独立代码复核又发现失败重试会重复用户消息、城市深链未同步和移动导航状态遗漏。修复后重新执行原始流程、失败重试、城市深链和手机导航，没有再出现页面错误。没有改动后端接口或模型配置。
